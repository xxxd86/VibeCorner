# 设计取舍：向千问 / 豆包 / Meta Muse 学什么，又在哪里自己做主

> **V2 已升级产品定义**：本文写的是 V1 的界面与视觉取舍（仍然有效）；
> 产品层面的定义变更（「位置先于尺寸」、依据可核查、反操纵承诺）见 [PRODUCT-V2.md](PRODUCT-V2.md)，
> 证据见 [RESEARCH-CAT.md](RESEARCH-CAT.md)（猫行为学，30 条）与 [RESEARCH-PSYCH.md](RESEARCH-PSYCH.md)（决策心理学，28 条）。

> 这份文档回答一个问题：同一个"拍张照给建议"的功能，为什么我们做成现在这个样子。
> 结论先说：**对话不是主体，判断才是主体；照片不是素材，是工作台。**

## 1. 先把三个参照物拆开看

### 1.1 千问 / 豆包：把"模型能力"翻译成"界面语法"

它们真正做对的不是"有个输入框"，而是三件界面语法：

1. **输入框是唯一中枢**。文字、图片、文件、语音都从同一个入口进，用户不需要先选"我要用哪个功能"。
2. **回复是结构化产物，不是一段散文**。模型输出被解析成卡片、表格、步骤、可点选项——
   用户扫一眼就能决策，不用读完一大段再自己提炼。
3. **等待被设计过**。流式文字 + 可折叠的"思考过程" + 骨架屏，让 3—8 秒的延迟变成"它正在干活"而不是"它是不是卡了"。

→ **我们取**：单一输入中枢、结构化卡片流、流式 + 可折叠思考过程、骨架屏。

### 1.2 Meta Muse（Ray-Ban Display 的产品设计）：辅助而不打扰

Muse 的设计约束很硬——**你的眼睛在现实世界，屏幕只是附加层**。由此推出来的原则：

1. **内容优先，chrome 极简**：没有多余的工具栏、没有多层导航，注意力只落在一条信息上。
2. **渐进披露**：先给一句结论（"这个角落可以继续"），想看细节再展开，而不是一上来堆满参数。
3. **深色沉浸画布**：看图/看内容时，界面退到背景里。
4. **单手可操作、大点击区、少选择**：每一步只问一件事。

→ **我们取**：一句话结论优先（verdict → 展开）、右侧画布做成深色沉浸区、每轮只问 1—2 个尺寸、按钮大拇指可达。

### 1.3 猫角落自己的约束：不越级承诺

产品纲领里最硬的一条是**分级信任**：L0 只能给方向，L1 才能给可执行建议，关键尺寸缺失就不许下"能放下"的结论。

这是设计问题，不是文案问题——**界面必须让"我知道多少"变得可见**。所以我们把"确定性"做成了视觉元素：

- 每个结论旁边都有等级徽章（`L0 · 方向预览` / `L1 · 可执行`）
- 尺寸条件用三态（✅ 满足 / ⚠️ 未知 / ❌ 冲突），**未知和冲突一样显眼**
- 被阻断的方案不是藏起来，而是单独一张卡写明"为什么不行、什么条件下才可能行"

> 大多数 AI 产品在努力显得确定；这个产品必须**诚实地显得不确定**，并让不确定性可读。这是它和其他"AI 建议"类产品的分水岭。

## 2. 由此得到的五个设计创新

### ① 空间画布（Spatial Canvas）——照片是工作台，不是缩略图

一般做法：上传图 → 下面吐一段文字。我们把照片变成可交互的工作台：

- 模型返回**归一化 bbox 热区**（0—1 坐标），画布上叠加圆角框 + 序号 + 结论色
- 点热区 → 高亮对应的方向卡；点方向卡 → 画布高亮该区域
- **点选模式**：用户可以在照片上戳"我想放这里"，坐标回传给模型做针对性评估

这一条把"看图说话"变成"对着图讨论"，是纯聊天界面给不了的。

### ② 测量卡（Measurement Card）——把最枯燥的一步做成体验

量尺寸是这类产品的必经环节，也是最容易掉人的地方（纲领里明确"每轮最多 2 项"）。
所以我们不做好几页的表单，而是：

- 一张卡只问 1—2 个尺寸，卡片上画清**端点、单位、为什么量**（"低于 60cm 猫会绕着走"）
- 大号数字输入 + `cm` 后缀 + 一个"不确定，先跳过"
- 顶部进度环显示还差几项，**用户可以随时停在 L0 走人**

测量不是代价，是产品在证明自己专业的地方。

### ③ 不买东西模式——复用与新品同权

纲领明确"不强制购买或凑 SKU"。所以方案里「复用你已有的」「挪一下现有家具」「什么都不买」和「买新品」是同级卡片，
0 元方案优先展示。绝大多数推荐产品做不到这一点，因为它和商业模式冲突；我们先把"信任"放在前面。

### ④ 猫视角雷达——把不可量化的东西诚实可视化

藏身感 / 通道 / 日照 / 安静 / 动线，五个维度 0—5 分，标注"启发式参考，非实测"。
它不参与 L1 通过判定，但能解释"为什么这个窝猫可能不用"——这是尺寸之外用户真正在意的东西。

### ⑤ 交付可带走——结果要能离开屏幕

一键导出标注图 PNG（2× 重绘 + 图例 + 等级水印）+ 现场清单可勾选。
用户拿着手机在店里买猫窝时，需要的是这张图，不是这个网页。

## 3. 视觉决策

| 维度 | 决定 | 为什么 |
|---|---|---|
| 主色 | 陶土橙 `#D2603A` + 纸面暖白 `#FAF6F0` | 猫、木、家 = 暖；同时避开"AI 科技蓝紫"的通用脸。克制使用：只出现在主操作、等级徽章、选中态 |
| 画布 | 独立深色区 `#141110` | Muse 式：看图时界面退后；也与左侧对话区形成"分析 / 空间"的物理分区 |
| 字体 | Inter / PingFang SC，正文 15px / 行高 1.6 | 中文正文 15px 比 14px 更耐读；行高 1.6 是中文长句的舒适区 |
| 圆角 | 8 / 12 / 16 / 22 / 28 五档 | 不做"全 24px"的偷懒统一；层级越高圆角越大，形成视觉秩序 |
| 阴影 | 暖色阴影（`rgba(60,40,25,…)`） | 灰黑阴影在暖色底上会脏 |
| 动效 | 卡片入场 stagger 40ms、按钮按下 0.98 | 只动 `transform/opacity`，尊重 `prefers-reduced-motion` |
| 图标 | 内联 SVG，`stroke-width:1.6` | 不用 emoji 当图标（跨平台渲染不一致，廉价感） |

**明确拒绝**：紫色渐变、重度玻璃拟态、满屏投影、渐变文字、"一站式/赋能/极致"式文案。

## 4. 界面结构（为什么是三栏而不是单列聊天）

```
┌──────────┬─────────────────────────┬──────────────────┐
│ 会话栏    │ 会话流（判断与卡片）      │ 空间画布（照片）   │
│ 248px    │ max 760 居中            │ 400px 深色        │
│          │ 输入中枢固定在底部        │ 测量进度 + 交付   │
└──────────┴─────────────────────────┴──────────────────┘
```

- **左**：历史角落 = 用户自己的"改造档案"，几秒就能回到上次没量完的角落
- **中**：判断、理由、测量卡、交付包——**"说"的部分**
- **右**：照片、热区、测量进度、导出——**"看"的部分**

聊天类产品默认单列，因为这个产品有"空间"这个第二客体，单列会把照片压成缩略图。
手机上退化为单列 + 底部抽屉，画布随时可召唤。

## 5. 每个环节的情绪目标

| 环节 | 用户此刻在想 | 界面的任务 |
|---|---|---|
| 打开 | "这玩意儿能帮我什么" | 一屏说清价值 + 三个能立刻照做的示例，不要功能列表 |
| 上传后 3 秒 | "它看懂了吗" | 立刻指出照片里的具体区域（"电视柜右侧墙角"），证明不是模板回复 |
| 看 L0 | "所以能改吗" | 给结论 + **一项缺失信息**，让人知道下一步干什么，而不是泛泛鼓励 |
| 测量 | "好麻烦，值得吗" | 每问一项就说清"为什么量"，可跳过，进度可见 |
| 拿 L1 | "我该买哪个、放哪" | 尺寸条件先于商品；未知项显眼；给出不买东西的选项 |
| 离开 | "下次还找它吗" | 能导出、能回看、能删数据 |

## 6. V3：闭环完成感与「家庭社交」（为什么不是公开社区）

V1/V2 把「给建议」做完了，但漏了一件事：**给出方案的那一秒，用户其实还没满足**。
他要的是「这件事定了」。所以 V3 的全部设计都围绕一个词：**收束**。

### 6.1 收尾卡：把"服务结束"换成"结论成立"

普通 AI 产品的结束是一句"希望对你有帮助"。我们的结束是一张卡：

```
已完成 · 这个角落的结论
这个角落已经有结论了：有条件可放
  3          6              3 + 6
你量的数    位置判断    尺寸条件 + 现场动作
接下来 7 天怎么判断（可展开）
[导出标注图] [分享给同住的人] [记录改造结果] [复制现场清单]
```

三个数字是刻意的：**你亲手量的数**（IKEA 效应：这份方案是你的）、**位置判断 6 项**（我们真的检查过）、
**条件 + 动作**（可执行）。它不是统计面板，是"这件事办成了"的证据。

### 6.2 社交：Muse 的一刻，不是广场

Meta Muse 的社交不是"发朋友圈"，而是**把当下看到的一刻变成可流转的东西**。
这个产品的使用场景天然是家庭决策（猫窝放谁房间、砂盆谁清理），所以社交单元是**「住在一起的人」**：

- 分享出去的是 `/s/<token>` 只读页：结论、位置 6 项、三态条件、方案——**不含**输入记录、点选、画像
- 24 小时过期、可随时撤销、只给同一 Wi-Fi；图片是 900px 缩略图（**拿不到原图**）
- 家人不用登录：支持 / 犹豫 / 反对 + 一句话；匿名自动叫「家人 N」
- 主人回来看到「家人意见」卡——**决策从"我的判断"变成"我们商量过"**

为什么不做公开社区/社会证据：那会立刻和「可信」冲突（假评论会伤到品类级信任，见 RESEARCH-PSYCH §3），
而这个产品的核心资产恰恰是"它说的话可信"。

### 6.3 改造前后对比：让结果可见

上传改造后的照片 → 生成前后对比卡（可编辑一句总结、可导出 PNG）。
这是唯一能让用户**看见自己做成了一件事**的东西，也是下一轮社交的天然素材（同一张对比图可以给家人看）。

### 6.4 装进主屏

`manifest.webmanifest` + maskable 图标 + `100dvh`/safe-area 布局：
手机「添加到主屏幕」后全屏打开，没有地址栏，像原生应用。这是"现代应用"的最低门槛。

## 7. 下一步（如果继续做）

1. **真实测量辅助**：手机陀螺仪/AR 粗测 + 用户校准，减少输入负担（不做像素反推）
2. **多角落档案**：同一户型的多个角落共享尺寸，量过的不再问
3. **SKU 巡检**：商品库过期检测 + 人工核对工作台（纲领 F6/F12）
4. **落地回访**：第 7/14 天轻量回访卡，验证"愿意行动"这条门槛
5. **改造后对比的社交延伸**：同一 token 下让家人看到"前后对比"，形成家庭内的改造记录
