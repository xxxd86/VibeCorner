# 演示视频（真实录制，非合成动画）

| 文件 | 尺寸 | 时长 | 说明 |
|---|---|---|---|
| `corner-demo-phone.mp4` | 390×844（竖屏） | ~109s | **主推**：手机端完整旅程，含全屏标注查看器 |
| `corner-demo-desktop.mp4` | 1440×900 | ~92s | 桌面三栏版，适合投屏/分享 |

> 两个视频都是**真实录制**：真实 DeepSeek 调用、真实家庭照片（洗衣机旁 / 三个敞口砂盆）、真实分享与投票接口。
> 不是剪辑合成，也没有预置答案；录完脚本会自检「测量值是否真的落库、方案是否真的生成」。

## 视频里的完整故事（phone 版，11 个段落）

1. `0:00` 欢迎态：三句价值主张 + 三张真实示例卡（含「0 元方案」）
2. `0:08` 上传一张**没收拾的真实角落照片**（洗衣机 + 玻璃门 + 杂物）
3. `0:14` 照片质检：指出「右侧白墙墙角、三个敞口盆压在地面中间」，可重拍也可继续
4. `0:22` **L0 方向预览**：3 个方向，其中至少 1 个不花钱；每张卡写清「先量什么 + 风险」
5. `0:30` **全屏标注查看器**（手机端核心交互）：照片 + 编号热区 + 图例 + 缩放/点选，一键关闭
6. `0:40` **渐进测量**：一屏一问，写清端点/单位/为什么量；填 `62cm` 提交
7. `1:05` **生成可执行方案**（演示解锁，不扣款）
8. `1:10` **交付包**：`位置`（6 项判断 + 依据徽章）→ `尺寸条件`（三态：通过/待确认/经验阈值）→ `清单`（第 1/3/7 天看什么）
9. `1:30` **分享给同住的人**：24h 有效、只在家里网络可打开、可随时撤销
10. `1:38` 家人打开只读页 → 点「支持」+ 一句留言 → 已告诉 TA
11. `1:48` 你切回应用：**「家人意见」卡**（1 人看过 · 支持 1 · 犹豫 0 + 留言 + 未读角标）
12. `1:56` 结尾卡

## 一处刻意的「不完美」

这版视频里，最终方案的结论是 **`信息不足 · 先量现有物品的外径和占地`**，而不是「可以放」。

这是产品刻意为之，也是它与其他「AI 给建议」产品最大的区别：
方向选的是**复用现有砂盆**，而「现有盆多大」只能靠用户自己量外径——产品不会编一个尺寸把结论凑成「可放」。
画面里的 `尺寸条件` 三项（通道净宽 / 墙角 A 边长 / 可用进深）都显示 **通过**，说明已量的部分确实够用；
它只是诚实地指出**还差一个信息**。

如果换成「买新品」方向，结论会是 `有条件可放`。这也是产品真实行为，不是脚本开关。

## 怎么重新生成

```powershell
# 前置：服务端在跑（node app/server/index.mjs 或 run.cmd）
node --experimental-websocket scripts/make-demo-video.mjs --w=390 --h=844 --out=docs/demo/corner-demo-phone.mp4
node --experimental-websocket scripts/make-demo-video.mjs --w=1440 --h=900 --out=docs/demo/corner-demo-desktop.mp4
```

脚本做四件事：
1. 清空会话（保证从欢迎态开始），用 CDP 真设备仿真打开应用；
2. 依次执行「上传 → 质检 → L0 →（手机端）全屏标注 → 测量填值 → 生成方案 → 切 tab → 分享 → 家人投票 → 回执」；
3. 用 `Page.startScreencast` 抓每一帧，按真实时间轴 + 等待段加速合成；
4. 调 `ffmpeg`（来自 `pip install imageio-ffmpeg`）编码成 H.264 MP4，并在结尾自检落库数据。

字幕与光标由脚本注入页面（`#demo-cap` / `#demo-cursor`），不是后期贴的字幕，所以重新录制永远和真实界面一致。
